# 家家乐蛋糕店 · 微信蛋糕预订演示版

本项目实现需求方案的第一阶段：**原生微信小程序 + Node.js 演示服务 + 使用相同接口的浏览器体验页**。商品为三款示例蛋糕，采用奶油色设计与代码绘制的蛋糕插画。无需安装项目依赖。

当前付款、退款、身份登录、手机消息均为**演示实现**，不会扣款或发送真实通知；不能直接用于正式营业。项目明确拒绝 `NODE_ENV=production` 或 `PAYMENT_MODE=live`，避免把演示收款误当作真实收款。

## 本机立即体验

需要 Node.js 22 或更新版本，在本目录运行：

```powershell
node server/index.js
```

打开 [浏览器演示](http://127.0.0.1:3100)。客户端默认以演示客户身份进入；右上角「店员入口」的本机演示口令为 **246810**。进入店员工作台后仍可返回客户页，两种身份的令牌互相独立。

数据自动保存在 `data/store.json`，写入使用临时文件、同步落盘与原子替换。重启服务后，订单和未过期会话保持；会话有效期为 12 小时。默认仅监听本机。演示服务为单进程，不能让多个实例共同写同一数据文件。

可复制 `.env.example` 为 `.env` 修改端口、数据文件或店员演示口令。勿提交数据文件、会话、真实联系方式或密钥。

## 在微信开发者工具中运行

1. 启动上述服务。
2. 在微信开发者工具中导入**项目根目录**，读取 `project.config.json`。已准备 `touristappid` 演示配置；如果工具不支持游客项目，填写自己的小程序 AppID。部分工具版本及游客模式可能限制真机预览。
3. 服务地址位于 `miniprogram/config.js`，默认 `http://127.0.0.1:3100/api`。仅在本机开发时关闭 request 合法域名校验；项目开发配置已关闭该检查。
4. 编译后使用「挑选蛋糕」「我的订单」「门店与我的」。店员入口在「门店与我的」页面。

真机上的 `127.0.0.1` 指向手机，不能连接电脑。若要局域网演示，在电脑使用自定义口令启动，例如：

```powershell
$env:HOST='0.0.0.0'
$env:DEMO_STAFF_PIN='请替换成自己的演示口令'
node server/index.js
```

将 `miniprogram/config.js` 改为电脑局域网 IP，两台设备连接同一网络。系统防火墙和微信真机域名限制可能需要另行配置。本版本不适合公开互联网部署。

## 已实现的业务规则

- 初始商品：草莓云朵、可可心语、蜜桃花园；规格、口味与价格可由店员维护，支持上下架。
- 一个订单预订一个蛋糕；价格取自服务端在售商品，客户端无法改价，已有订单保留商品与价格快照。
- 所有营业和交付日期校验采用 `Asia/Hong_Kong` 时区；默认每日 08:30–19:30，仅可选择未来且在营业时段内的时间。
- 自取或免费配送，配送必须填写地址。由店员逐单确认档期和能否送达；不接入地图、自动接单上限或第三方配送。
- 店员确认后才允许付30%定金；金额以整数分计算并四舍五入到分。200元蛋糕付60元定金、交付时付140元尾款。
- 收款阶段：`待确认 → 待定金 → 预订成功 → 制作中 → 待交付 → [配送中] → 已完成`。拒单须说明原因；未收齐尾款不能完成。
- 线上模拟尾款与线下登记互斥；线下收款支持现金和门店收款码。登记会关闭尚未完成的模拟线上尾款请求，避免重复记账。
- 取消/改期先提交申请，由店员同意或拒绝。同一订单仅允许一条待审申请；待审期间冻结付款和制作进度操作。
- 取消时店员填写退款金额，可退0元或不超过已付线上金额；线下尾款如需退还，由店员线下处理。退款结果在审核后单独模拟，可模拟失败再重试，不重复入账。
- 客户只能看自己的订单；店员权限由服务端会话决定，传入 `role`、客户ID或修改页面路径不能获得权限。
- 店员工作台显示待确认、待付定金、制作交付、售后申请统计及演示提醒。浏览器订单页定时刷新；小程序店员订单页定时刷新，客户订单支持返回页面刷新、下拉刷新及详情手动刷新。
- 地址、电话、正式上线时间、预算及具体售后政策仍待定；客户端明确展示缺失地址、电话，不使用虚构联系方式。

## 验证

```powershell
node --test tests/domain.test.js tests/http.test.js tests/repository.test.js tests/wxml.test.js
node scripts/check.js
```

自动化测试覆盖订单全流程、配送、失败重试、重复支付结果、线上线下尾款竞争、权限隔离、退款与改期审核、日期规则、商品快照、持久化回滚及 WXML 运算符回归。静态检查覆盖 JS/JSON 语法、微信页面文件、WXML 插值表达式语法、绑定、闭合标签及事件方法。

已通过浏览器的真实界面操作验证预订、店员确认、模拟定金、制作、模拟尾款和交付，并检查桌面及390px手机布局。**尚未在微信开发者工具中编译或真机验证**，静态检查不能替代微信工具验收。

## 熟客真实试用前必须完成

目前已交付演示阶段，以下属于正式接入工作，尚未完成：

1. 补齐真实商品照片、规格、口味和价格，门店地址、电话、营业休息安排、取消改期与退款政策。
2. 注册、配置小程序账号与微信支付商户号，完成所需的主体和小程序关联手续，并确定正式部署预算和日期。
3. 用服务端 `wx.login` code 换取微信身份，店员使用服务端 OpenID 白名单或等效的授权管理。移除演示客户创建接口与演示口令登录。
4. 实现微信支付适配器：定金和尾款分别创建商户支付单，前端调用真实微信支付；服务端验证通知签名、解密回调、校验商户/应用/支付单及整数分金额，处理幂等与主动查单。客户端返回成功不能作为收款依据。
5. 实现微信退款适配器：关联真实支付单、处理多笔付款拆分退款、通知验签、退款处理中/成功/失败与重试。与线下收款竞争时，真实已扣款不能仅拒绝入账，必须建立异常款处理和退款补偿。
6. 核实当前微信类目可用的消息模板与订阅授权，接入真实手机提醒并验证送达；不能假定每个订单都能无条件推送。
7. 切换到 HTTPS、微信合法域名、正式数据库及备份；支付与消息密钥仅在服务端保存，补齐监控、用户隐私说明和平台发布流程。
8. 验收真实支付失败、重复通知、退款结果、店员授权、客户数据隔离、手机布局与真机操作，再开放熟客试用。

## 项目布局与接口

`miniprogram/` 为微信源代码；`server/` 包含共享业务规则、持久化及HTTP接口；`web/` 是可直接体验的浏览器前端；`tests/` 为测试。

所有受保护接口使用 `Authorization: Bearer <token>`。公开配置可读取，但所有订单、付款和管理操作均在服务端授权。

| 接口 | 用途 |
| --- | --- |
| `GET /api/config` | 演示模式、门店配置、服务端时间 |
| `POST /api/session` | 创建本机演示客户会话 |
| `POST /api/staff/login` | 演示店员口令登录，错误尝试限流 |
| `GET /api/products` / `PUT /api/products/:id` | 商品列表 / 店员维护 |
| `GET, POST /api/orders` / `GET /api/orders/:id` | 订单列表、预订和详情 |
| `POST /api/orders/:id/confirm` / `progress` | 店员接单、拒单与进度 |
| `POST /api/orders/:id/payments` | 创建定金或尾款模拟支付请求 |
| `POST /api/payments/:id/simulate` | 客户模拟支付结果 |
| `POST /api/orders/:id/offline-balance` | 店员登记线下尾款 |
| `POST /api/orders/:id/requests` / `review` | 客户申请与店员审核 |
| `POST /api/refunds/:id/simulate` | 店员模拟退款结果与重试 |
| `GET /api/notifications` / `POST /api/notifications/read` | 演示消息及已读 |
| `PUT /api/settings` | 店员维护营业、联系方式、售后规则 |

支付与退款的 `simulate` 接口仅供本机演示，不能当作真实支付回调接口。参考平台接入入口：[微信小程序文档](https://developers.weixin.qq.com/miniprogram/dev/framework/)、[微信支付商户文档](https://pay.weixin.qq.com/doc/v3/merchant/)。
