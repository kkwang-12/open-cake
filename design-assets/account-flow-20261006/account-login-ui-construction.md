## 2. 总体视觉
- 保留参考图的暖白底、白色卡片、黑色胶囊、灰色说明、细线菜单图标。
- 字体继承现有系统无衬线字体栈；不用手机外框、状态栏截图、原生胶囊假图或位图文字。
- 页面背景 #FAFAF8，卡片 #FFFFFF；主文字 #111111、正文灰 #666666、辅助说明 #888888。
- 本页层级按文字职责区分，主欢迎语适度粗，说明和菜单正文普通字重。
- 两页按参考图展示 LUNE 字标和欢迎文案；两页文案集中定义，方便后续统一替换。正式 app 名称、业务门店参考数据与云配置不因视觉提案变更。
- UI 中不展示开发环境、云服务诊断、接口名称等实施信息。

## 3. 我的首页：施工结构
保留 pages/account/account 路由、现有 tabTransition 与共享底部导航。替换现有 ACCOUNT / Hello 大字和英文菜单前缀为参考图结构：

### 3.1 品牌与设置
- LUNE：文字节点，建议22px/300、字距5px、单行；与页面左边缘对齐。
- 设置齿轮：独立黑色细线 SVG，显示20px、点击44×44px。
- 先使用 safe-area.measure() 得到真实状态栏、导航行与原生胶囊区域。品牌行和设置按钮安排在可用区域，不将齿轮放到原生胶囊下方重叠的位置。
- 若同一导航行右侧空间不足，将完整品牌／设置行置于导航安全区下方，用正常文档流展示，不用负边距挤入胶囊。
- 不修改共享 page-header，以免影响其他页面。

### 3.2 头像与欢迎区
左侧64px圆形中性头像；右侧依次为：
- 「你好，欢迎来到 LUNE」：16px/600/1.45。
- 「登录后查看订单与收藏」：12px/400/1.5，#888。
- 「登录 / 注册」：小黑胶囊；可见高度32px、文字13px/500，触摸区域至少44px。
- 图文间距12px，文字自然换行；窄屏不缩小欢迎语来挤单行。
- 默认头像为独立SVG或纯形状资源，灰色圆底＋中性人物，不使用用户头像或假身份。

### 3.3 三项统计
白色卡片、三列等宽、轻分隔、无阴影：
- 我的订单：显示「—」。
- 我的收藏：显示「—」。
- 收货地址：只读取当前本机地址服务的真实条数；无法读取／当前模式不可用显示「—」，不能把错误当0。
- 不写死图中的2个地址，不调用未开放的个人统计接口。
- 数字建议20px/600/1.25，标签12px/400/1.4；卡片高约72px、圆角12px。
- 三项的点击目标和下方对应菜单一致，复用原有订单／收藏／地址路由。
- 本轮不因“未登录”视觉新增全局登录拦截。

### 3.4 生日蛋糕横幅
- 左右16px；参考高度约128px、圆角12px；图文独立节点。
- 左侧文案：「生日蛋糕」「为特别的日子」「定制专属蛋糕」「立即定制 →」。
- 标题18px/600/1.4，说明12px/400/1.5，入口13px/500。
- 右侧独立草莓蛋糕图片，占横幅约55%–60%；主体不要进入左侧文字区。文字不烘焙到图片。
- 参考中的入口是简洁文字箭头，不额外加第二个大黑按钮。
- 现有项目没有定制表单，本期点击进入选购页；不创建定制订单或自动选某个未经确认商品。
- 图像失败保持横幅尺寸，保留文案与可用入口。

### 3.5 六项菜单
一个白色圆角区块，顺序为：
我的订单、我的收藏、收货地址、客服与帮助、门店信息、关于 LUNE。
- 每行最小48px，自然内容高度；文字14px/400/1.4。
- 左侧独立20px细线图标，图文间距12px；右侧统一小箭头，整行可点。
- 分隔线 #ECEAE6、1px，左右遵循内容基线；最后一行无底线。
- 图标按订单／收藏／位置／耳机／门店／信息语义组织；优先复用已有合适的SVG，新增缺失的独立图标。
- 当前 service/store/about 的信息反馈沿用现有门店资料／准备中反馈，不因这轮UI产生假客服或假门店页面。
- 原“隐私与服务说明”不作为第七条菜单塞入参考首页；欢迎页协议链接使用现有准备中反馈。
- 开发验证区不进入本次产品视觉；原诊断方法留存，不通过改云配置或放开旧演示实现隐藏。

### 3.6 底部导航
直接复用 custom-tab-bar，选中我的：
- 当前已确认参数：左右24px、高58px、圆角29px、底7px＋安全区。
- 图标与选中表现沿用现有共享组件，本轮不修改导航，以免影响所有主页面。
- account 内容底部使用 --tab-page-bottom-padding；最后一行能滚到导航上方。
- 不按截图画第二套导航，不强行让所有内容塞首屏。

## 4. 欢迎登录页：施工结构
建议新增 features/login/login.{wxml,wxss,js,json}，登记 features 子包与 routes.pages.login。
属于前端UI路由；不新增身份服务动作。

### 4.1 顶部导航
- 左侧浅灰圆形关闭图标，可见圆约28px，触摸44×44px。
- 中间「欢迎登录」14px/500；右侧保留真实微信胶囊，页面不实现假“…”。
- 安全区与标题避让来自 safe-area.measure()；导航行有明确高度。
- 关闭与“暂不登录”走同一返回函数：有前页返回、无前页回我的，不回首页。

### 4.2 品牌与主视觉
居中 LUNE 字标＋小号 PÂTISSERIE，建议字标30px/300、字距5px；副标8–9px，作为品牌装饰而非交互说明。
- 圆形暖米色草莓蛋糕主视觉：常规屏直径约200–220px，短屏缩到约160–180px，保持完整蛋糕与装饰。
- 品牌、图片、文字各为独立节点；主体保持比例，不拉伸。
- 欢迎语「你好，欢迎来到 LUNE」24px/600/1.3，居中；窄屏自然两行。
- 副文案「珍藏每一个甜蜜时刻」13px/400/1.5，#888。
- 品牌到图片12–16px，图片到欢迎语20px，欢迎语到副文案6px；均为建议起点，可随实测调整。

### 4.3 双登录按钮
黑色「微信快捷登录」、细描边「手机号登录」，上下间距12px，左右各24px。
- 黑色主按钮直接引用 action-capsule.wxss 的 .action-capsule，不覆盖共享58px高、29px圆角、18px/500。
- 黑白两按钮保持同宽同高；描边按钮用本页独立样式，细边框 #E5E2DD、白底黑字。
- 微信与电话图标显示20px，文案保持视觉中心。图标以独立SVG表达，不能用emoji或文字字符替代。
- 它们是UI入口，本期不调用真实登录、手机号或短信接口。
- 未勾选时点击微信：在协议附近给出「请先阅读并同意相关协议」反馈。
- 勾选后点击微信：提示「登录功能正在准备中」，保持本页；不更新个人身份、不显示登录成功。
- 手机号按钮：提示「手机号登录正在准备中」，保持本页；不创建输入或验证码页。本期只展示入口，不在进入未实现流程前强制同意协议。
- 占位反馈只在用户点击时出现，不把技术说明永久印到产品界面。

### 4.4 协议与继续浏览
- 默认不勾选，状态仅保存在当前页内存，不写入账号／存储，不等于真实协议授权。
- 复选图形建议18px，触摸区44px；说明12px/400/1.5。
- 「已阅读并同意」灰色，《用户协议》与《隐私政策》黑色，可独立点击，点击链接不触发勾选。
- 未有真实正文时给现有“资料正在准备中”的明确反馈，不捏造协议正文、不使用空跳转。
- 「暂不登录，继续逛逛」13px/400，触摸高44px，返回我的或实际前页。
- 勾选后去掉局部提醒；关闭页不保存假同意记录。
- 不新增协议确认弹层；这是后续登录功能阶段的范围。

### 4.5 整体适配
- 页面主体为正常文档流，常规屏以有节奏的留白呈现；短屏先减少主视觉和区块间距，再允许滚动。
- 双按钮、协议和底部入口不使用固定绝对坐标；不靠把协议字号降到不可读来塞首屏。
- 底部只留一次安全区；不挂tab-bar，不引用主页面的导航底部占位。
- 本页无输入框，无需在这轮创建键盘／验证码状态。
- 图片加载失败保留同尺寸品牌占位，布局稳定。

## 8. 施工顺序与验收
1. 准备必要的独立图片和图标；先核对主体位置与字体基线。
2. 完成我的首页；核对统计、横幅、六菜单和导航占位。
3. 完成欢迎登录页及仅有的前端往返；核对关闭、协议与占位反馈。
4. 按项目已有脚本检查路由、WXML／JS静态和图标引用、源包体；新增页面纳入实际静态检查。
5. 针对新增地址计数／页面往返／勾选点击隔离做必要验证，不为纯颜色／留白写镜像测试，不声称已验证真实登录。
6. 用户在开发者工具编译并真机验收；按375／390逻辑宽度作为主要参照，同时查看320／430、较短屏和系统大字体。
7. 有新问题再修，达到两页视觉确认后同步实际字号与布局记录；其他页面后续逐页处理。

本轮完成标准：
- 页面是可交互的原生UI，不是整屏图片。
- 参考的结构、暖白黑色与文字层级吻合；按钮执行现有基线。
- 不遮原生胶囊、末行不被导航挡住；小屏可滚，文字不截断。
- 地址数真实，订单收藏为—，无硬编码身份或假登录。
- 欢迎页能打开、关闭和继续浏览；协议点击与勾选互不误触。
- 现有菜单和主导航可用；没有新登录拦截影响其他功能。
- 未接功能只在点击后给准确反馈；没有把手机号／验证码／协议弹窗扩入本轮。
