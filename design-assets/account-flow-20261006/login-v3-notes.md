## 视觉设计
1. 借鉴大幅圆形主视觉、居中信息、宽幅黑白双按钮、充足留白；LUNE 字标与草莓蛋糕承担品牌识别。
2. 登录操作直接放在页面上，减少 v2 的卡片包裹。主登录黑色，手机号入口细描边，协议与继续浏览使用小号辅助文字。
3. 协议确认使用遮罩加白色圆角弹窗。主操作为「同意并继续」，次操作为「暂不同意」。
4. 手机号独立为输入步骤：大号数字、区号、细分隔、清除操作，以及「获取验证码」。
5. 验证码独立为六格输入步骤：当前格黑色焦点、灰底其余格、重发倒计时。填满后进入真实验证码校验，不在初始状态增加重复登录按钮。
6. 参考图的豆包人物换为 LUNE 蛋糕摄影；登录方式展示微信／手机号。未引入抖音、飞书、运营商本机号认证或其协议。
7. 图片中的号码是虚构示例；品牌与蛋糕图为设计提案。主按钮落地仍复用 miniprogram/styles/action-capsule.wxss，截图近似形状不覆盖共享按钮源码参数。
8. 暖白 #FAFAF8、黑色 #111111，系统无衬线字体、14px 正文、12–13px说明；新页主标题建议24–26px/600。大号手机号建议22–24px，而非全页文字加粗。参数属于建议值，最终真机确认。

## 流程分支
### 微信分支
欢迎登录 → 微信快捷登录 → 如未勾选，打开协议确认 → 同意并继续 → 调用真实微信身份能力 → 服务确认登录成功 → 返回原入口。
同意协议不是身份认证成功，也不是自动完成下单。
已勾选直接发起身份登录；拒绝授权／取消停留登录，允许继续浏览。
资料服务未接入时，不提供可执行的假登录按钮。手机号权限按真实必要动作单独请求，不把头像昵称授权当登录前提。

### 手机号分支
欢迎登录 → 手机号登录 → 如未勾选，打开协议确认 → 同意并继续 → 手机号输入 → 获取验证码 → 发送成功进入六格验证码页 → 校验成功 → 返回原入口。
图板底部流程文字表示手机号分支；微信快捷分支不需要再输入手机号或验证码。
协议确认发生于用户触发需要协议的动作，而不是进入页面就强制弹窗。
手机号页面可携带上一页用户主动同意的状态；直接打开且未有本次同意状态时显示未勾选，获取验证码时按同一机制提醒。
协议确认中的「暂不同意」关闭弹窗，不发请求；保留原页面输入。「同意并继续」勾选本次状态并仅恢复一次用户选择的动作。

## 手机号输入
- 仅按实际服务支持的地区处理。大陆示例显示 +86 与11位合法号码；未实现多地区能力时区号为静态前缀，不开放选择器。
- 页面直接使用手机号输入；本机号免短信认证不是本稿设计能力，不宣称已经接入运营商服务。
- 手机号格式不完整时主操作禁用或点击后就地提示，遵循实际校验策略。图中展示有效号码已填入的可发送状态。
- 请求中显示「正在发送…」，防重复。发送失败保留号码、可重试，不提前进入倒计时／验证码页。
- 发送由服务确认成功后开始建议60秒倒计时，使用真实截止时间，返回前台不重新开始。
- 「首次登录将自动创建账号」仅在真实服务支持该行为时展示。
- 返回登录首页保留本次合法输入；离开会话不长期保存验证码。

## 六格验证码输入
- 六格视觉由一个真实数字输入能力承载，保持连续输入、退格、粘贴、自动填充与焦点体验；不要设计六个难以切换的独立文本框。
- 图中是空输入、首格聚焦、短信已发送的状态。键盘为演示清晰未绘制；真实界面需要键盘可见时仍能看到输入区和重发入口。
- 六位为本稿示例，实际位数须与服务端验证码要求一致。
- 填满后只发起一次校验，请求中防重复、不因页面更新反复提交。展示「正在验证…」状态；服务确认前不能显示登录成功。
- 失败保留手机号，在格下说明「验证码错误，请重新输入」或真实过期／限流原因，允许修改。网络失败可以明确操作「重新验证」，不要不停自动重发校验。
- 倒计时结束恢复「重新发送」，重新发送成功才重启计时；服务端限流规则优先。
- 返回手机号输入页允许修改号码；换号需重新发送，不能沿用旧验证码。
- 成功消费一次内部返回意图，回订单／收藏／我的等实际来源。无合法来源回我的；取消不能执行原动作。

## 协议与可访问性
协议与隐私政策使用真实已发布正文，返回时保留登录上下文；无正式正文时不使用假链接。
协议默认不勾选，弹窗只在相应动作触发；不同意不阻止公开浏览或本机地址管理。
勾选、关闭、返回、登录方式切换点击范围至少44px。较大系统字体允许协议自然换行。
验证码错误使用文字和颜色共同表达，不只依赖颜色。加载提示与输入阅读顺序一致。
原生微信胶囊／状态栏通过 safe-area 实测避让；侧边24px、共享58px主按钮及底部安全区只计算一次。
生成图为概念审阅，实际小程序字号、触摸与键盘适配以源码实现和用户真机验收为准。
