# 后续 UI 调整指南
记录日期：2026-10-06
来源：用户转交的后端 UI 建议；作为后续工作安排，不代表后端能力已接入或页面已验收。用户最新页面范围和已确认字体／组件优先。

## 当前工作
本轮只施工「我的首页」的未登录产品 UI 与已有入口；账户资料和真实登录状态暂不接入。独立登录页不在本轮新增。先前两页施工方案仅执行我的首页部分。
已确认的首页、详情和购物袋按需要微调；不因记录本指南而批量改版。
后续按用户逐页安排执行，不把推荐顺序当作自动授权实施全部页面。

## 注册页面口径
按当前注册统计：4 个主页面 + 9 个业务页面 = 13 个，不计 legacy 旧演示。
下表名称对应当前路由；原建议的「订单确认页」暂对应已注册的 order-success 结果页面，正式显示名称后续确认，不与填写订单混淆，不因此新增页面。

| 建议 | 页面 | 可以做到什么程度 |
|---|---|---|
| 现在优先做：2 个 | 我的、地址管理 | 优化完整布局和已有本地交互；账户资料与登录状态暂不接入 |
| 现在可以做：6 个 | 首页、选购、商品详情、购物袋、填写订单、我的收藏 | 已有本地展示或交互，可调整字体、留白、控件、动效及异常状态 |
| 先做 UI 预览：3 个 | 订单列表、订单详情、订单确认页／当前订单结果页 | 用隔离的开发数据设计各状态；真实订单、付款结果和操作需后续联调 |
| 建议暂缓：2 个 | 商家管理、独立规格页 | 商家页等待实际运营流程接线；规格已在详情弹层实现，独立页面暂不重复建设 |

| 页面 | 当前注册路由 |
|---|---|
| 首页／选购／订单列表／我的 | pages/home/home；pages/shop/shop；pages/orders/orders；pages/account/account |

| 订单结果／订单详情／地址管理／我的收藏／商家管理 | features/order-success/order-success；features/order-detail/order-detail；features/addresses/addresses；features/favorites/favorites；features/admin/admin |

## 需要等待的内容
| 内容 | 等什么 |
|---|---|
| 独立登录页、手机号授权、个人资料编辑 | 明确账户与授权需求，并接入真实身份和资料保存 |
| 付款、取消、退款、核销等操作的成功反馈 | 真实云端结果与业务流程接通 |
| 预约日期／时段的真实可选状态 | 云端营业规则、容量和报价接入 |
| 客服、隐私与售后正式内容 | 真实联系方式及正式政策确认 |

## 推荐顺序
我的 → 订单列表 → 订单详情 → 地址管理 → 订单确认／结果页。

订单相关页面可以现在完成视觉设计，后续再接真实数据；云环境未开通不妨碍 UI 预览。预览数据必须与真实业务隔离，不展示为真实订单、不创建生产记录，不让模拟点击进入真实付款／核销结果。

## 复用与验收
- [字体与布局规范](UI-TYPOGRAPHY.md)：购物袋与选择规格基线，文字职责对应字体；具体数值以页面源码为准。
- [动画规范](UI-ANIMATIONS.md)：复用已确认动效，不扩大改动范围。
- 黑色全宽主按钮复用 action-capsule；底部主导航复用 custom-tab-bar。
- 只读本机统计不等于云端账户资料；模拟登录、订单成功和已核验预约不能混入产品状态。
- 最终视觉由用户编译并真机确认，静态检查不能替代。
