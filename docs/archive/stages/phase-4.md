<a id="b01-b02-cart-service--b01--b02-离线购物袋接口编排"></a>
# B01 / B02 离线购物袋接口编排

日期：2026-10-04。实现为 `cloudfunctions/_shared/cart-service.js`；测试为 `tests/cart-service.test.js`。

<a id="b01-b02-cart-service--已完成范围"></a>
## 已完成范围

`createCartService({runTransaction, now, newLineId}).execute(event, principal)` 接收 D07 已定义的 `cart.get/add/update/remove` 请求。principal 必须由 D06 `resolveCustomer` 根据可信平台上下文及当前用户记录生成，复制或伪造对象不能使用。平台 context 不允许来自请求 payload；每次网络调用仍需重新验证当前用户状态。

获取 / 首次添加使用环境、AppID、用户、门店构成的确定性袋 ID。空袋 GET 返回 version 0，不写记录。更新 / 删除读取指定 cartId 后验证所有权。所有变更检查袋版本，更新 / 删除另查行版本；稳定 lineId、lineVersion 按 D03 规则保留或递增。请求不能夹带 ownerId、userId、价格或角色。

返回仅包含 cartId、storeId、version、lines；每行包含 lineId、lineVersion、productId、skuId、quantity、cakeMessage、addedAt、updatedAt。私有 owner、留言摘要、库存资源和价格快照不返回；商品展示及当前价格读取由 B05 补齐，不能用此结果直接结算。

复用 D03 目录、SKU、数量和留言规则，不复制业务逻辑。相同 SKU 与 NFC/trim 后的相同留言合并；不同留言、不同 SKU 分行，价格相同也不能误合并。合并数量仍受 SKU / 门店限额约束。缺正式经营限制拒绝添加和更新，不用测试数值兜底。移除下架 / 缺目录行不依赖商品和经营配置。

变更幂等键按环境、AppID、用户、动作隔离；规范请求摘要覆盖 payload。原子记录命令回执，相同键与请求重放原始结果；相同键换参数报 IDEMPOTENCY_KEY_REUSED。原始回执可能比当前购物袋旧，客户端必须 GET 后再继续新操作；不能把重放结果当作当前全局版本。删除后重试原加购回执也不会复活已删除行。

本服务不读取库存余额、不预扣库存、不占预约容量、不创建订单或支付。规格的 stockRequirements 只用于验证目录完整性。

<a id="b01-b02-cart-service--存储接入约定与未完成项"></a>
## 存储接入约定与未完成项

`runTransaction(work)` 必须提供原子事务 session：

| 方法 | 约定 |
|---|---|
| readCart(id) / readReceipt(id) | 当前事务读取，缺失返回 null |
| readCatalog(productId) | 当前产品及完整 SKU 列表；缺失返回 null |
| readLimits(storeId) | 已发布且服务端可信的购物袋限制；缺失不兜底 |
| saveCart(cart, expectedVersion) | 条件写入；null 表示仅不存在时创建，整数表示比较当前版本 |
| saveReceipt(id, receipt) | 仅不存在时创建，与 cart 原子提交 |

目录、限制与购物袋读取也必须参与事务一致性检查。事务失败全部回滚；无变化 UPDATE 仍提交回执，但不写袋或增加版本。事务重试调用服务端时钟和 ID 工厂，不接受客户端时间 / ID。

没有提供实际微信云数据库适配器或新增可部署 cart 云函数，也没有接到本机 LOCAL_DRAFT 购物袋。回执格式是此服务内部约定，后续数据库集合落地应与 D04 幂等字典对齐并补保留策略、响应校验及真实并发验收。禁止直接用无条件 set 或仅在事务外检查版本替代上述协议。

# B04 本机冲突与重试

日期：2026-10-04。完成本机防重入、冲突恢复和加购回执；真实云网络超时 / SDK 并发仍待验收。

<a id="b04-cart-retry--实现与行为"></a>
## 实现与行为

详情页为每次加购生成本机 operationId，重试相同规格 / 数量 / 留言沿用原键。规格、数量、留言或目录版本改变形成新意图；用户看到已验证成功后，再次主动加购使用新键。页面 hide / show 或重新加载仍保留尚未确认的意图；旧请求未完成时，额外的 in-flight 标记持续阻止提交，不因 load 重置界面而重复发送。

local-bag 将回执与实际袋行放在同一个本机存储值中，一次 setStorageSync 写入，然后读回核对。相同键 / 规范化请求重放原始回执，不再次合并数量；相同键改参数拒绝。配置等待期间的两个相同请求也只写一次。回执在行删除后保留，旧加购重试不复活已删除行。读取回执不依赖当前目录可用性，也不更新价格或证明当前可购买。

operationId 仅是本机草稿相关标识，采用时间 / 序列 / 随机片段，不能用于身份、支付或替代 D04 服务端键。AppID 存储分区继续沿用；无云用户所有权 / 跨设备能力。旧调用未提供键仍支持，当前详情页始终提供键。

袋中数量是绝对值更新，选择 / 移除检查本机 revision。失败后只重新读取实际存储，不自动重放 delta / 删除操作；旧 revision 冲突时展示已刷新的当前快照，必须由用户重新操作。若刷新本身失败，保留“购物袋读取失败”，不能宣称“已刷新”。卸载页面不渲染异步结束状态。

回执无自动淘汰或虚构 TTL；本机配额失败仍报保存失败，不能丢弃未核实回执来强行成功。详情页未确认意图目前保存在页面实例中；整个进程重启后，只有调用者仍携带原 operationId 才能使用存储回执安全重试。正式云接入时还需持久化待处理命令、对齐 D04 回执存储 / 保留政策与真实网络恢复，不把此实现报告为完整云链路。

# B05 商品与购物袋行复核

日期：2026-10-04。本机目录 / 规格 / 价格复核及微信模拟器验收完成；库存快照检查完成离线模型测试，真实云库存与正式购买仍待接入。

<a id="b05-cart-review--当前行为"></a>
## 当前行为

Bag 每次 onShow / 重试都异步调用 local-bag.review，读取当前规格配置。等待期间清空已选小计、禁用操作；隐藏页面及被新请求替代的响应不再渲染。复核结束同时检查存储 revision，避免展示被另一操作改动或删除前的快照。单行目录异常保留该行，不能使其他正常商品消失。

| 状态 | 展示和操作 |
|---|---|
| LOCAL_READY | 当前本机配置与快照一致，可勾选 / 调数量；仍不是正式可购买 |
| PRICE_CHANGED | 展示原单价与当前单价；确认前不可勾选或调数量，不计已选小计 |
| CONFIG_CHANGED | 名称 / 规格描述 / 版本 / 规格标签已变；展示当前名称与规格，需确认 |
| PRODUCT_UNAVAILABLE | 已下架或不存在，可查看 / 移除，不可勾选 |
| SKU_INVALID | 原规格 / 组合失效，不猜另一 SKU 替换；可查看 / 移除 |
| QUANTITY_INVALID / MESSAGE_INVALID | 数量或历史留言不合新规则，提示重新选择；原值不静默清除或截断 |
| REVIEW_FAILED | 配置异常或临时读取失败，提示重新核验；不冒充商品下架 |

所有行仍 checkoutAllowed=false、stockStatus=UNKNOWN。有效行的已选件数 / 小计单独计算，全选只处理可勾选行；本机读取时不改写存储、不永久改变用户勾选。原始数量和角标计数包含袋内全部行，失效行排除于已选摘要。

确认更新使用原生 showModal。取消或确认期间隐藏不写入；同意后服务再次读取当前配置、比较 reviewToken 与 revision，规则或价格又变时拒绝过期确认。成功更新该行的本机名称、规格描述 / 标签、版本、单价，保留 lineId、数量、留言及原勾选意图。回执不被修改；原加购重试仍重放原始命令结果，不是对当前价格的确认。

specification.get 对开发目录中合法但不存在的商品返回 PRODUCT_UNAVAILABLE；重复 ID / 结构错误仍 INVALID_RESPONSE，不把配置损坏当下架。development / shell 门禁保持不变，无生产回退到开发示例。

实现：`miniprogram/utils/bag-review.js`、`services/local-bag.js` 与 `features/bag`。reviewToken 是本机一致性比较，不是签名、权限或报价凭证。目录复核不承担云端身份、库存、经营配置、预约或价格权威。

<a id="b05-cart-review--库存离线准备"></a>
## 库存离线准备

`cloudfunctions/_shared/stock-review.js` 的 reviewStockDemand(lines, resources) 复用 D03 aggregateStockRequirements 与 D04 validateResource。在可信服务端快照上，按共享 resourceId 聚合各行需求，扣除 held / confirmed / consumed；余额不足或资源关闭返回 INSUFFICIENT，缺快照 / 记录返回 UNKNOWN，充足返回 SUFFICIENT。跨门店、重复 / 非法记录拒绝。

该函数没有读写数据库、不预扣库存、不暴露资源 ID 和余额，任何结果都 checkoutAllowed=false。尚未接入实际云处理器或本机 Bag；不能宣称真实库存不足 UI 已完成联调。真实商品资源数量、经营配置与 SDK 事务仍待云环境及资料。

# B06：有效勾选行与 Checkout 输入

2026-10-04。本机链路与服务端离线模型分别实现；正式报价、库存、履约、订单和付款继续关闭。

购物袋「核对商品」先重新复核当前目录，只收集有效已选行。输入保存在 AppID 分区的 `jiajiale.local-checkout-selection.v1`，包含袋 revision、行 ID 和复核 token，不保存可作为权威使用的金额。此 token 是本机快照比较值，没有鉴权或云签名能力。保存并读回成功才导航；重复点击、页面隐藏后的迟到响应不触发导航。

Checkout 展示名称、规格、原留言、数量、当前本机商品小计。每次显示重新读袋和目录，比较 revision、有效勾选集合及 token；数量、留言、勾选、删除、新增或商品配置改变后，旧输入失效，清空金额并提示返回重新选择。重新进入可恢复有效输入；不清空购物袋、不生成订单，不把 UNKNOWN 库存当可售。

本机未选行和失效行均不进入核对页。原勾选值及失效行仍保留在袋中；失效行可以查看或移除。本机预览并不证明留言、经营数量限制、库存或云身份已经正式有效。

`cloudfunctions/_shared/checkout-selection.js` 是内部离线函数，复用 D06 可信 principal / 本人校验、D03 Cart / SKU / 数量 / 留言规则。输入严格只有 `cartId / expectedVersion / lines[{lineId, expectedLineVersion}]`；拒绝重复或不存在行、旧版本、伪造身份和额外价格 / 数量字段。商品价格、数量和留言全部从服务器可信袋 / 目录取得，当前配置重新核验并用安全整数分求和。返回 `checkoutAllowed=false / stockStatus=UNKNOWN`，没有 handler、SDK 事务、库存预留或正式 Quote。

云接入时，Cart、目录和经营限制必须来自同一一致读快照；金额与身份禁止使用客户端投影。当前本机 draft 不发送到上述正式 Cart 接口，必须另行迁移并由云校验。

1. 创建订单持久化实际选中行的 `cartId / lineId / lineVersion`，以及对应数量、规范化留言、商品 / SKU、addedAt 的内容摘要；身份与门店来自云。稳定行 ID 不得在删除后复用。
