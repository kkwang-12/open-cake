# 小程序 UI 字体规范

基线日期：2026-10-04。基于用户已确认满意的购物袋与商品详情「选择规格」界面，含现有规格弹层；商品展示卡片采用第 6 节用户最新确认的首页卡片规范，作为后续所有商品卡片的统一基线。用于后续页面的设计与微调，不授权批量重做页面。本轮仅记录规范，不修改现有界面。

## 1. 字体与风格

- 字体沿用 `styles/tokens.wxss`：`-apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", sans-serif`。使用系统无衬线字体，不额外引入字体文件；实际字形由设备系统决定。
- 正文默认字重 400；按钮重置后继承字体，局部样式覆盖字号与字重。
- 主要文字 `#111111`，数量数字 `#000000`；正文灰色 `#666666`，商品规格/留言灰色 `#777777`，次要说明 `#888888`；黑色按钮白字 `#FFFFFF`。
- 页面背景当前实际为 `#FAFAF8`，表面色为 `#FFFFFF`。这是现有代码值，不将“白色风格”误记为所有背景均为纯白。
- 层级通过字号、字重与灰阶表达。标题和重要金额粗，商品名称适度粗，规格与说明使用普通字重；不把所有文字统一加粗。
- 字号优先使用逻辑 `px`，不按截图物理像素实现。布局可使用 `vw`/`rpx`，保持现有手机适配。`rpx = 屏幕逻辑宽度 / 750`，仅在 375px 宽屏幕上 2rpx 约等于 1px。

## 4. 后续页面统一映射与建议

| 信息角色 | 建议基线 | 使用方式 |
|---|---|---|
| 一级页面标题 | 32px / 700 / 行高 1.3 | 购物袋同级标题；商品详情名称保留 28px |
| 弹层或二级标题 | 20–21px / 700 | 以现有规格弹层 21px 为参照 |
| 商品/订单条目名称 | 16px / 600 / 行高 1.45 | 列表商品、订单商品名称 |
| 普通正文、表单标签 | 14px / 400；分组标题 600 | 按内容职责区别正文与标题 |
| 商品规格、次级信息 | 13px / 400 / 行高 1.5 | 避免与名称同样粗黑 |
| 列表单价 | 16px / 600 | 与商品名称同一行且不重叠 |
| 关键总金额 | 26–28px / 650–700 | 独立汇总优先 28px/700；紧凑弹层保留 26px/650 |
| 全宽黑色主操作按钮 | 20px / 500 / 白色 | 复用 `.action-capsule`，不另写重复字号 |
| 数量数字 | 列表 15px / 600；弹层 17px / 600 | 与控件尺寸匹配，不强行同号 |
| 次要说明、计数 | 11–12px / 400 | 长正文和关键操作条件不降至 10px |

微调其他页面时：先标明现有字号、字重和颜色，再按上述角色给出目标值及原因；只在用户请求的页面内落实。保留业务规则、交互逻辑及已经确认的其他页面布局。先处理同级字体不一致，再处理间距，不通过整体缩放页面匹配参考图。

上表的商品条目与列表单价建议用于购物袋、订单等信息行；上下分区的商品展示卡片统一执行第 6 节的 14px 名称、11px 描述、15px 价格及配套布局，不沿用信息行的 16px 字号。

## 5. 与字体配套的已确认组件

- 共用主按钮：58px 高、32px 圆角、20px/500 白字、黑色 #111111。底部容器左右 5.5vw，底部 18px 加一次安全区距离。定义在 `miniprogram/styles/action-capsule.wxss`。
- 购物袋：112×128px 商品图、12px 圆角；图片到信息区 16px。名称与单价顶端对齐，规格和留言紧接下方。无「单价」标签和行金额显示；右侧底部为数量控件及黑色垃圾桶。
- 购物袋数量胶囊：浅灰 #F3F2F0，两端 32px 圆按钮 #EAE9E7，15px/600 黑色数字；加减号为专用黑色加粗 SVG。垃圾桶图标 22px，点击范围 44px。
- 商品与下方分隔线留白 8px，下一行间距 10px。商品多时可滚动，底部操作区实测高度用于内容留白。
- 字体/布局最终视觉效果由用户编译后真机确认；静态检查或回归测试不能替代真机视觉验收。

## 6. 所有商品卡片的统一设计规范（2026-10-04，用户已确认）

设计基线：用户标注参考图的「上方图片、下方商品名称／商品描述／商品价格」两区卡片，以及按该参考完成的首页推荐卡片。后续所有新建或修改的商品展示卡片（首页推荐、选购列表、搜索结果、收藏等）均复用此设计，不因所在页面不同另设字体或扩大留白。用户后续明确指示优先。

以下数值为已确认首页卡片的当前实际值，同时作为后续商品卡片的目标规范。代码来源：`miniprogram/components/product-card/product-card.wxml`、`miniprogram/components/product-card/product-card.wxss` 的 `.card-home`，以及 `miniprogram/pages/home/home.wxss` 的商品网格。

### 6.1 结构、比例与背景

| 项目 | 统一规范 |
|---|---|
| 整体结构 | 一个完整卡片容器，上方图片区、下方独立信息区；名称、描述、价格依次纵向排列 |
| 卡片宽度 | 填满网格列宽；两列等宽，不通过整体缩放卡片改变字号 |
| 卡片外观 | 白色 `#FFFFFF`，圆角 10px，溢出裁切；无描边、无阴影，外部 margin/padding 为 0 |
| 图片区 | 宽度为卡片宽度的 100%，高度约为宽度的 82%，块级显示，无图片下方基线空隙 |
| 图片裁切 | `aspectFill`，保持图片比例并裁切填满；图片与信息区直接衔接，无额外分隔空白 |
| 图片圆角 | 图片自身圆角为 0，由外层卡片裁切形成上方圆角；图片底边不单独做圆角 |
| 图片占位 | 背景 `#EFEDE8`；文字 12px/400、`#666666`、行高 1.5，水平及垂直居中 |
| 信息区 | 白底，内边距上 6px、左右各 12px、下 8px；三行文字共用左对齐基线 |

首页当前图片高度为 `calc(41vw - 18.04px)`，对应页面左右各 16px、列间距 12px 的两列网格，即卡片宽度 `(视口宽度 - 44px) / 2` 的 82%。后续其他容器按实际卡片宽度保持这一比例，不直接照搬依赖首页视口宽度的公式。三行内容均为单行时，信息区总高度约 75px。

### 6.2 字体、颜色与行高

字体统一继承系统无衬线字体栈：`-apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", sans-serif`，不另外引入字体文件。

| 文字职责 | 字号 | 字重 | 颜色 | 行高 | 排版 |
|---|---:|---:|---|---|---|
| 商品名称 | 14px | 600 | `#111111` | 1.4（19.6px） | 单行、左对齐，超出省略号 |
| 商品描述 | 11px | 400 | `#888888` | 1.4（15.4px） | 单行、左对齐，超出省略号 |
| 商品价格 | 15px | 600 | `#111111` | 1.4（21px） | 左对齐，完整显示 `¥`、金额及「起」等价格后缀 |

名称和描述使用 `white-space: nowrap`、`overflow: hidden`、`text-overflow: ellipsis`。描述不预留两行高度，`min-height: 0`；保留原始完整商品数据与详情页入口，不为适配卡片改写或截断数据。

### 6.3 区内间距与商品间距

| 间距 | 统一规范 |
|---|---:|
| 图片底边至名称行盒顶部 | 6px（信息区上内边距；名称 margin-top 为 0） |
| 名称行盒底部至描述行盒顶部 | 2px |
| 描述行盒底部至价格行盒顶部 | 3px |
| 价格行盒底部至卡片底边 | 8px |
| 左右相邻卡片边缘间距 | 12px |
| 上下相邻商品行的卡片边缘间距 | 12px |

以上间距按行盒及卡片边缘计算，不按字形可见笔画计算。商品网格使用两列 `repeat(2, minmax(0, 1fr))`、`gap: 12px`；拆成多个网格时，相邻网格之间也只保留 12px，避免叠加 margin 与 gap。首页当前网格距页面左右各 16px，栏目标题到网格的留白属于页面布局，不计入卡片内部间距。

### 6.4 应用与验收

- 当前实际实现仅首页 `typography="home"` 已采用本规范；其他页面是否已统一，必须以实际代码为准，不因本文件更新而声称已完成迁移。
- 后续在用户请求范围内新建或调整商品卡片时，优先复用现有 `product-card` 结构与这套样式；迁移到共享默认样式时保持上述数值一致，不重复创建近似版本。
- 本次只记录统一规范，不批量修改选购、收藏等页面。购物袋和订单的信息行、商品详情及规格弹层继续遵循各自已确认规范。
- 商品名称、价格、图片加载失败占位和点击进入详情的交互应保留；视觉规范本身不新增收藏等业务功能。
- 最终字体字形、图片裁切、卡片比例及纵向间距由用户编译后真机确认。用户最新明确指示覆盖本节，后续确认的改动应同步更新实际值与规范。
