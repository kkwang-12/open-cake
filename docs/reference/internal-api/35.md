## A05 内部离线门店 / 配置维护（2026-10-06）

既有 admin.store.update / config.save / config.publish / slot.update 和 store.get / config.get / configs.list / slots.list 由 merchant-store-service 的内部 execute 实现可离线部分，不改变 PLANNED 状态或真实 handler / 客户端 allowlist。所有返回 scope OFFLINE_MERCHANT_*，cloudVerified / callable / operationsAllowed false；CommandResult 仍为 entityId / version / errorCode。当前用户和同店 CONFIG_WRITE 每次重验，跨店拒绝。

ConfigDraft 严格 9 个经营字段：fulfillmentModes、timePolicy、deliveryRules、cartLimits、quoteTtlMinutes、paymentHoldMinutes、slotPolicy、tradePolicyVersion、fulfillmentPolicyVersion；id / 状态 / 序号 / 发布时刻不能由 draft 注入。支持显式未完整草稿，发布须完整且经服务端正式资料验证。已发布记录不能 save，发布 CAS 配置及门店、序号单调，原 key 可重放但不得绕过当前权限。

非空 slotPolicy 的 releasePolicyVersion 仅接受 `slot-release-policy.js` 导出的已实现版本；null 可保存未完整草稿但不能发布。新 quote.create 必须读取受支持配置，将版本捕获到 appointmentSnapshot，重验报价时版本改变/缺失即拒绝。order.create 原样捕获快照，SLOT reservation 同步记录该版本；报价、订单和名额记录不得混用。策略含义唯一来源是[时段取消规则](../../FULFILLMENT-RULES.md#取消后的时段名额回补)。缺少字段的历史记录保持原义，不由当前配置推断新策略；不接受任意字符串作为正式规则。

START_MAKING 的新版本 requiredAtomicEffects 同时含 CONSUME_STOCK_RESERVATIONS / CONSUME_SLOT_RESERVATION；名额与库存、订单、制作日志和回执须原子保存，新增名额资源及reservation各1次CAS写。readMerchantOrderState / readResolutionState / readDeliveryState / readPickupState 须提供对应制作日志，资源验证会核对 resolutionLogId、resolvedAt 和 ACCEPTED→MAKING；相关日志也必须进入事务读保护。取消与开始制作竞态须由订单版本及完整读集裁决，不能在事务外先释放名额。完成保持已消耗名额，不产生资源回补写入。

mapSelectionToken 仅供可信事务适配器绑定当前人员 / 店 / scope / 版本解析，不接受原始 location。地址改变撤销旧定位。store.update 不修改 activeConfigId，配置发布才可原子切换指针。slots.list 返回持久资源事实，缺行不声明可下单；slot.update 不能改时段身份 / 模式 / 计数，V1 容量固定 3 / 1，CLOSED 禁约而非清零。config.get 无 configId 时返回当前发布配置，无配置则 NOT_FOUND，不返回虚构草稿。

StoreDraft / ConfigDraft / SlotResourceList 是白名单投影；ConfigSummaryPage 当前使用相同配置 DTO 的 HMAC 分页，绑定当前人员 / grant / 店 / 内容修订，实际 SDK 有界读取待补。审计保留请求 / 实体 / 关联写入摘要与脱敏信息，不记录完整政策 / 地图 token / 电话。完整说明与 MS01–MS07 见 [A05](../../archive/stages/phase-8.md#a05-merchant-store)。
