# X01 本人地址云接口

本节定义地址提供方与客户端契约；部署、进度和验收只维护 CURRENT-STATUS。六个 action 沿用 action 清单，不新增管理员或测试写入口。

## 身份与数据边界

- 每次调用先检查平台 AppID/环境/OPENID、输入白名单与当前 ACTIVE users。请求不能传 ownerId、角色、已验证坐标或集合名；地址从可信用户 ID 绑定所有权；他人地址/不存在地址在公开层统一 NOT_FOUND，内部 FORBIDDEN 不泄露存在性。
- create/update/get 只投影 Address，附 apiVersion 和 userVersion；list 返回 Page<Address>，附 userVersion/defaultAddressId。setDefault 返回 userId/version/defaultAddressId/userVersion，remove 返回 entityId/deleted/userVersion。所有成功响应另附平台身份生成的 subjectHash（与 user.me 一致），用于隔离本机命令草稿；它不是授权凭据。userVersion 是 users.version，不是地址 version；列表客户端据指针计算 isDefault，不落库 isDefault。
- 当前联系电话规则 CN_MOBILE_FORMAT_V1 只检查现有表单的中国大陆 11 位手机号格式，不验证机主。手填省市区允许 regionCodes 三项均 null、location=null；有编码或选点 token 必须通过可信校验，当前入口直接 LOCATION_REQUIRED，不伪造位置或配送资格。
- 客户端 addresses.enabled 默认 false；开启云地址后不读取/导入本机地址簿。写前先读当前用户列表，本机待提交命令保存至按 AppID/阶段/环境/subjectHash 隔离的草稿键；未知结果使用原键重试，成功刷新同用户云列表后清除。不自动重放草稿、不将草稿显示成已保存云地址；配送结算尚未接入时云地址选择不导航到结算。

## 用户版本与事务

- 一次成功的新地址写命令在同一 SDK 事务写地址（如需）、幂等回执，并真实更新现有 users.version/updatedAt/defaultAddressId。create/update 即使不改变默认指针，也推进用户版本；setDefault 即使指针相同，也推进一次版本。所有地址写提供方必须遵守同一用户版本写保护，客户端直接写全部拒绝。
- 更新地址检查 expectedVersion；setDefault/remove 另检查 expectedUserVersion。默认地址删除与清空指针原子，不自动选另一个地址；其他地址编辑保留当前指针。保护借助现有用户版本，不新增未定义的 fence 字段，不证明 D04 完整订单方案已接通。
- 原生 SDK 每次重试重新读取并校验当前用户，最多 2 次重试（3 次 callback）。业务/保护/回执同事务；SDK 冲突/回滚/竞争必须通过真实环境验收，不以模型串行队列代替。
- 幂等 ID 绑定环境/可信 actorScope/address.action/key；业务指纹排除 idempotencyKey/requestId。幂等集合使用既有字段，SUCCEEDED 回执 result 只保存 entityId/version/errorCode，不保存 Address、电话、联系方式或原始响应。重放重新检查当前用户、目标归属/删除状态，并投影当前实体；create/update 重放目标已删除时 NOT_FOUND，不复活地址。remove 可重放本人软删除结果。

## 分页、预算与索引

- list 使用 ownerId + deletedAt=null，updatedAt DESC/_id DESC，页大小默认 20、最大 50，最多取 pageSize+1 条。seek 的整个 OR 与可信 owner/deletedAt 过滤 AND；不读全表再过滤。
- 游标复用 D07 HMAC/15 分钟/至少 32 字节密钥，额外绑定当前 users.version。地址修改或默认指针变化后旧游标 CURSOR_INVALID，跨用户/环境不通用；每页加载当前 ACTIVE 用户。
- 索引：addresses(ownerId ASC,deletedAt ASC,updatedAt DESC,_id DESC)。幂等回执按完整确定性 _id 主键读取/新增，不提供任意回执列表。
- 单 callback：新 create/update 最多 4 个单文档读取（用户、回执、目标及写前复核）、3 个写入（地址、回执、用户）；setDefault 最多 3 读/2 写，remove 最多 4 读/3 写；get 2 读/0 写，回执重放 3 读/0 写。入口另有 1 次用户读取。每次 SDK 重试重新计数；最重命令最多 13 次读/9 次写（包含入口和 3 个 callback），不把保护写遗漏。
- list 每 callback 1 用户读取 + 1 有界查询，查询响应不超过 2 MiB；入口另 1 用户读取。客户端连续分页最多 20 页，超限明确失败，不截断成完整列表；此为技术内存/请求预算，不是经营地址数量限制。
- 一次客户端写流程包含写前完整列表、1 次命令与写后完整列表，最多 41 次云函数调用；调用中用户变化会拒绝刷新/清理原用户重试键。列表两段各最多 20 页，失败保留原命令键，不循环自动重试。

## 部署配置与权限

独立函数目录 cloudfunctions/address；先运行 node scripts/prepare-cloud.js 同步共享代码，SDK 精确锁定 4.0.2。环境变量不得写入小程序配置；机密游标密钥由受控函数配置提供，缺任何必要项时入口关闭。

| 环境变量 | 值或要求 |
|---|---|
| JJL_APP_ID | 目标小程序 AppID |
| JJL_CLOUD_ENV | 当前目标环境 ID |
| JJL_STAGE | development/test/production，与目标一致 |
| JJL_ADDRESS_ENABLED | 仅明确开启时 true |
| JJL_ADDRESS_PHONE_POLICY | CN_MOBILE_FORMAT_V1 |
| JJL_ADDRESS_CURSOR_SECRET | 至少 32 随机字节的 base64；不进仓库、小程序、日志或普通证据 |

addresses/idempotency_records 客户端规则均为 read:false/write:false；保持既有 users 私有规则。address Event 函数拒绝匿名，且处理器始终再次验证原生上下文。部署工具仅安装代码不能证明函数配置/权限已生效，必须回读与原生拒绝请求验收。函数环境变量通过平台配置设置，参见[CloudBase 官方环境变量说明](https://docs.cloudbase.net/cloud-function/function-configuration/env)。
