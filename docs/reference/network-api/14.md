> G1 本人云购物袋的技术接口；部署状态、授权和验证只见 [CURRENT-STATUS](../../CURRENT-STATUS.md)。

## 原生选购草稿

- Event `cart` 提供 get/add/update/remove 四个 action，输入遵循 [registry](03.md)，输出遵循 [Cart DTO](04.md)。仅 development 且服务端 JJL_CART_ENABLED/JJL_CART_SELECTION_DRAFT 两个开关为 true 时允许；目录标识由 JJL_CART_STORE_ID 绑定。客户端也必须显式启用同目录的 cart.enabled，目录与草稿不跨环境。
- 原生 invocation 的 APPID/OPENID/ENV 是唯一身份来源；先核验 ACTIVE 用户，再在事务里重新授权。event 根部平台附加 userInfo/tcbContext 被忽略，业务 payload 的身份/价格/资源字段仍拒绝。匿名由函数安全规则拒绝。集合客户端读写拒绝，客户仅通过 Event action 访问本人袋。
- 每 owner/app/environment/store 一个确定性袋ID。加购必须带本人 get 的 cartId（registry 的可选字段保留离线服务兼容）；原生处理器将它与当前身份计算值比较，账号在 get 与写之间改变时拒绝。update/remove 同样检查 cartId，不查询或操作其他用户袋。
- 用户明确选择“选购草稿”：不因未知库存/提前量阻止保存；既有商品/规格身份、在售状态、正式数量范围和已知留言规范仍校验。未知值保持 null，不填默认经营值。未知留言长度仅允许空留言。resolveSku 的成交校验继续保留，购买/选择结算/订单/支付继续关闭；此模式不证明 D04 正式订单依赖读取保护。

## 原子性与回执

- `runTransaction(callback,2)` 内重新读取用户与袋；每次新命令写当前袋并增加袋版本（相同值新 key 也物理写），写成功回执，再更新 users.version/updatedAt。最后一写失败必须回滚全部；默认地址指针不变。确定性 `_id` 的 create-if-absent 阻止并发新建重复袋。不得用无条件 set 覆盖。
- 回执作用域为 environment + [appId,subjectId] + cart.action + key，指纹排除 idempotencyKey；业务版本与参数纳入指纹。持久化仅保留公共回执字段和 result={entityId,version,errorCode:null}，无行、留言、价格或响应快照。禁止将一般提供方失败标成已确认 VERSION_CONFLICT。
- 重放先重新授权并验证引用与版本，返回当前本人袋，当前袋可为空。原key异参拒绝；冲突败者不写回执或增加用户版本。此处重新投影的价格仅供显示；不承诺不同商品读处于同一价格快照。
- 客户端在 app/stage/environment/subjectHash 隔离的本机存储保存一个未确认请求，发送前校验写回；该记录只用于原键恢复，不作为云袋。未知结果保留原 payload/key/expectedVersion；刷新看到新版本或已移除行后也原样重试。存在未确认操作时不同意图返回 BUSY；明确终态错误清该操作，账号切换不复用其他人的草稿。不导入本机离线购物袋。
- 页面 reviewAll 刷新只有在当前袋版本已高于未确认请求的 expectedVersion 时才确认原key（只能重放或拒绝，不会新写）；这样删除行已消失也可清除已完成操作。版本未推进时刷新保持未确认记录，等待用户重试原意图；不在普通GET或页面刷新中自动执行新的写入。

## 传输与提供方预算

- 最多100行，持久化袋与投影各不超过2MiB；数量及行金额计算为安全整数。这是技术保护，不是经营数量上限。展示目录按10行一批，并复用相同商品/规格读取。
- 单次 GET：事务内用户/袋最多2次文档读取，无写；前置用户读取1次，展示最多200次文档读取。单次 add/update：前置用户读取1次，事务最多6次文档读取，最多3次写（袋/回执/用户）；remove 不读取目录来决定是否允许移除。重试最多由SDK重跑2次事务回调，不能增加业务key；以上为每个回调上限。
- 运行时 Nodejs20.19、wx-server-sdk精确4.0.2、timeout20s；无HTTP入口、触发器或定时任务，不需要TCP数据库/VPC。Native SDK 实际竞争/回滚/丢响应另验，离线 fake 只证明适配代码分支与失败时全量回滚义务。
- 单用户受控验证可使用1个本人袋、最多5条新回执；预期 add/update/竞争胜者/remove 四个成功命令、users.version +4，预留1条清理额度。固定 run/key，不重启整轮以规避预算；结果未知先读袋和回执，保留原key。完成移除所有本轮样例行，保留空本人袋及可审计回执，版本不回退。
