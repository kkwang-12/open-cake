> 门店公开读取技术约束；部署和验收状态仅查CURRENT-STATUS。

## store.get

请求为`{action:'get',payload:{storeId}}`，沿用原生身份、AppID与环境校验，拒绝请求或payload中的额外字段；仅允许服务端绑定的门店ID。客户端`store.enabled`与服务端`JJL_STORE_READ_ENABLED`均显式开启后才可使用；原有`store.health`不依赖此开关。未知action仍拒绝。

服务端在一次只读SDK事务内读取`stores._id`及该门店引用的`store_config._id`。每次查询最多2条以检测异常响应，单文档JSON上限64KiB；缺门店、非OPEN门店、非PUBLISHED或未生效配置、门店/配置引用不匹配及不完整时间策略均拒绝。事务显式冲突最多重试2次；只读快照不代表订单读取保护或容量预留。

成功data含`apiVersion/storeId/name/address/phone/timeZone/fulfillmentModes/policyVersion/slotMinutes/delivery/status`；businessHours仅投影`weekday/fulfillment/startMinute/endMinute`，dateOverrides仅投影`serviceDate/fulfillment/closed/windows[{startMinute,endMinute}]`。不得返回activeConfigId、私有配置、资源计数、密钥或完整云平台上下文；可信地图接入前不输出未经核验的坐标。

此读取接口不发布经营配置、不初始化日库存/时段、不生成报价、不创建订单；DRAFT记录不能当作OPEN返回。新集合客户端读写均应拒绝，原函数原生身份规则保留。

## store.slots.list

请求为`{action:'slots.list',payload:{storeId,fulfillment,serviceDate,productIds}}`，沿用同一原生身份及服务端读取开关，只读固定门店。productIds为1–60个不重复商品ID（读取预算，不是购物袋经营限额）；客户端不能提供提前量、时段ID、容量或资源版本。

服务端在一次只读SDK事务内读取门店、当前PUBLISHED配置、指定商品及确定性时段ID。仅本店ON_SALE商品参与，提前量取配置与各商品最大值；缺失提前量拒绝，不按0分钟补值。上海时区、可预约日期范围、营业窗口/临时闭店、半小时分段及严格提前量截止点复用正式报价的定义。最多100次文档读取、每文档64KiB，SDK冲突最多重试2次；不扫描整个时段集合，不依赖新索引。

成功返回apiVersion/storeId/fulfillment/serviceDate/timeZone/items；每项仅slotId/startAt/endAt/available/windowNature。缺失、满额、关闭或定义过期的资源available=false，闭店日items为空；资源计数异常拒绝。自取windowNature=PICKUP，配送为ESTIMATED。不返回占用数、剩余容量、内部保护计数、商品私有字段或数据库版本，不写任何资源/回执；列表仅供选择，报价及下单仍须重新校验，不锁定时段或商品库存。

## store.health 的可选门店位置证明校验

原生身份与环境校验保留。请求只允许action='health'、可选空payload及合法requestId，拒绝客户端提供证明ID、坐标、人员或角色；顶层平台传输元数据仍不作为身份来源。

JJL_STORE_LOCATION_PROOF_ENABLED默认关闭，关闭时沿用available/stage/environment响应且不读证明。显式开启后，服务端JJL_STORE_ID及JJL_STORE_LOCATION_PROOF_ID绑定两个固定ID；在一次只读SDK事务读取stores和location_verifications，按[字段字典](../data/collections/location_verifications.md)校验，成功只额外返回storeLocationVerified:true。缺失或不匹配返回CONFIGURATION_REQUIRED，不把错误当作已核验；内部异常脱敏。

该检查允许核验DRAFT门店，只说明读取快照中的门店版本/位置与受控证明匹配；不发布草稿、不启用store.get、不返回坐标/证明ID/POI/指纹，也不签发地址token或证明订单事务读取保护。store.get开关与DTO保持原状。

位置证明的内部`_transactionFence`允许为非负安全整数，只作数据库读取保护元数据处理，不参与证明业务字段的精确校验，也不修改证明或返回客户端；未知业务字段和异常计数仍拒绝。报价使用证明并递增内部计数后，health仍须验证同一实体版本、位置指纹和来源。
