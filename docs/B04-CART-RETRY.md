# B04 本机冲突与重试

日期：2026-10-04。完成本机防重入、冲突恢复和加购回执；真实云网络超时 / SDK 并发仍待验收。

## 实现与行为

详情页为每次加购生成本机 operationId，重试相同规格 / 数量 / 留言沿用原键。规格、数量、留言或目录版本改变形成新意图；用户看到已验证成功后，再次主动加购使用新键。页面 hide / show 或重新加载仍保留尚未确认的意图；旧请求未完成时，额外的 in-flight 标记持续阻止提交，不因 load 重置界面而重复发送。

local-bag 将回执与实际袋行放在同一个本机存储值中，一次 setStorageSync 写入，然后读回核对。相同键 / 规范化请求重放原始回执，不再次合并数量；相同键改参数拒绝。配置等待期间的两个相同请求也只写一次。回执在行删除后保留，旧加购重试不复活已删除行。读取回执不依赖当前目录可用性，也不更新价格或证明当前可购买。

operationId 仅是本机草稿相关标识，采用时间 / 序列 / 随机片段，不能用于身份、支付或替代 D04 服务端键。AppID 存储分区继续沿用；无云用户所有权 / 跨设备能力。旧调用未提供键仍支持，当前详情页始终提供键。

袋中数量是绝对值更新，选择 / 移除检查本机 revision。失败后只重新读取实际存储，不自动重放 delta / 删除操作；旧 revision 冲突时展示已刷新的当前快照，必须由用户重新操作。若刷新本身失败，保留“购物袋读取失败”，不能宣称“已刷新”。卸载页面不渲染异步结束状态。

回执无自动淘汰或虚构 TTL；本机配额失败仍报保存失败，不能丢弃未核实回执来强行成功。详情页未确认意图目前保存在页面实例中；整个进程重启后，只有调用者仍携带原 operationId 才能使用存储回执安全重试。正式云接入时还需持久化待处理命令、对齐 D04 回执存储 / 保留政策与真实网络恢复，不把此实现报告为完整云链路。

## 验证

新增 8 项测试，全套 246/246 通过：

- 实际存储已写入但读回抛错，复建客户端用同键重试不重复加量；目录暂不可用仍能重放。
- 并发重复加购仅写一次、不同键是独立添加、同键改参数拒绝、删除后重放不复活。
- 数量 / 删除已写入但反馈失败后，读取恢复不重复写；旧 revision 拒绝。
- 详情失败后保留键、输入变化使用新键、成功后新加购使用新键、页面隐藏 / 加载中防重入。
- 冲突刷新不自动覆盖新快照；刷新失败不虚报刷新成功。

静态检查 180 文件通过；主包源文件估算 2005/2048 KiB、features 40 KiB、legacy 45 KiB。图片与已验收详情 UI 保留。

微信模拟器真实加购草莓 6 寸×1，留言“B04重试验收-001”，实际存储包含行与加购回执。通过工具的 getStorage / setStorage，仅对该测试行取消勾选并增加 revision，模拟页面持有旧版本；实际数量按钮点击被拒绝，刷新后件数仍 5、已选 4、小计 892，并提示“购物袋已变化，已刷新，请重新操作”。用户再次点击才将测试行改为 2。移除测试行后，原有黑巧克力 6 寸×2、8 寸×2 的行内容 / 数量 / 金额 / 勾选逐行一致。
