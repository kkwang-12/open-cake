# B06：有效勾选行与 Checkout 输入

2026-10-04。本机链路与服务端离线模型分别实现；正式报价、库存、履约、订单和付款继续关闭。

购物袋「核对商品」先重新复核当前目录，只收集有效已选行。输入保存在 AppID 分区的 `jiajiale.local-checkout-selection.v1`，包含袋 revision、行 ID 和复核 token，不保存可作为权威使用的金额。此 token 是本机快照比较值，没有鉴权或云签名能力。保存并读回成功才导航；重复点击、页面隐藏后的迟到响应不触发导航。

Checkout 展示名称、规格、原留言、数量、当前本机商品小计。每次显示重新读袋和目录，比较 revision、有效勾选集合及 token；数量、留言、勾选、删除、新增或商品配置改变后，旧输入失效，清空金额并提示返回重新选择。重新进入可恢复有效输入；不清空购物袋、不生成订单，不把 UNKNOWN 库存当可售。

本机未选行和失效行均不进入核对页。原勾选值及失效行仍保留在袋中；失效行可以查看或移除。本机预览并不证明留言、经营数量限制、库存或云身份已经正式有效。

`cloudfunctions/_shared/checkout-selection.js` 是内部离线函数，复用 D06 可信 principal / 本人校验、D03 Cart / SKU / 数量 / 留言规则。输入严格只有 `cartId / expectedVersion / lines[{lineId, expectedLineVersion}]`；拒绝重复或不存在行、旧版本、伪造身份和额外价格 / 数量字段。商品价格、数量和留言全部从服务器可信袋 / 目录取得，当前配置重新核验并用安全整数分求和。返回 `checkoutAllowed=false / stockStatus=UNKNOWN`，没有 handler、SDK 事务、库存预留或正式 Quote。

云接入时，Cart、目录和经营限制必须来自同一一致读快照；金额与身份禁止使用客户端投影。当前本机 draft 不发送到上述正式 Cart 接口，必须另行迁移并由云校验。

O04 精准移除约定：

1. 创建订单持久化实际选中行的 `cartId / lineId / lineVersion`，以及对应数量、规范化留言、商品 / SKU、addedAt 的内容摘要；身份与门店来自云。稳定行 ID 不得在删除后复用。
2. 只有订单创建事务成功后才处理对应袋行，不能在进入 Checkout、报价、支付弹窗或客户端超时时清袋。
3. 在当前 Cart 版本上重新读并比较每条已下单行，ID、行版本与内容摘要均一致才删除。未选、新增、已修改、删除后重加行全部保留；不以旧袋全局版本变化为由清空或覆盖整袋。
4. 同一订单的移除结果需持久化去重；重放只返回既有结果。事务响应丢失先查询订单 / 回执，不重复创建。若移除使用补偿，失败保留待同步状态，重试仍比较版本及摘要。

上述移除为契约，实际订单事务与补偿由 O04 接入；当前不会自动删除已选本机草稿。
