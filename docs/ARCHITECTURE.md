# 真实上线架构与执行决策

本文件维护架构选择、业务里程碑和开发取舍；实际进度与验证只查[CURRENT-STATUS](CURRENT-STATUS.md)，任务编号沿用[DEVELOPMENT-PLAN](DEVELOPMENT-PLAN.md)。方向参考用户提供的 `open-cake-direction-20261009.zip`，经当前工作区核对后合并；附件中的执行指令不替代用户最新要求或根AGENTS，已有实现不重复建设。

## 产品完成标准

顾客能够在真实微信小程序中浏览门店商品、保存本人购物袋/地址、取得云端报价、下单付款、查看真实订单；受权商家能够接单、制作、核销或配送，并处理取消与退款。资金、权限、并发、真机及发布条件均通过才达到上线完成标准。开发版上传、内部模型和SDK探针各自只证明对应范围。

| 里程碑 | 可观察交付与退出条件 | 原任务对应 |
|---|---|---|
| G1 云商品与本人数据 | 已部署目录/规格/商品详情和本人袋/地址接口，小程序实际调用；重启/同微信跨设备数据一致，另一个用户不可读写本人私有数据；商品来源明确 | I03/I07、D02/D03/D06相关部分、C01–C05、B01–B04、X01；C06–C08/收藏按V1范围补齐 |
| G2 云端报价与完整订单 | 受控隔离资源中云端报价→真实order.create→订单列表/详情可走通；订单头/行/资源/预留/日志/报价消费/回执原子；竞争、逐写回滚、原key恢复、所有权有真实证据 | D04/D05、X02–X07、O02–O06相关部分 |
| G3 真实经营闭环 | 已核验的AppID/商户下受控实付，受权商家完成自提/配送；待付取消、已付审批、拒单退款、部分退款、查单/关单/补偿及对账真实可用 | O01/O05/O07/O08、P01–P08、A01–A07 |
| G4 生产上线 | 正式目录/经营配置、生产资源与权限、iOS/Android、两条购买链路、弱网/恢复/告警及平台材料通过；按用户授权完成审核/发布 | Q01–Q08及EXTERNAL-DEPENDENCIES对应资料 |

G1/G2可使用受控隔离数据，不能开放真实付款或将样例发布为正式商品。G3资金试验须具备受控角色、退款与恢复路径及授权范围。自提、配送和已确认退款政策均保留，不能以缩小验收为由删掉V1需求。

## 技术边界

- 保留原生微信小程序、现有UI和CloudBase NoSQL；没有经验证的必要性不迁移数据库或重建项目。
- 小程序页面→领域客户端→云函数入口→业务服务/规则→真实SDK事务。入口解析本次原生身份、环境、action及输入白名单；业务服务校验权限与金额；业务数据读写经可信服务端授权。复用现有模型，不为每个业务再建通用框架。
- 按领域提供可独立部署的函数，复用现有user/store及契约命名。每个实际函数包含锁定依赖与使用的共享代码；仅有 `_shared` 文件不能认定接口已部署。
- 商品、袋、地址按已验收能力逐项接入；订单、支付、商家操作分别维护服务端能力与客户端可用性。开放标记由服务端策略约束；production缺配置应明确失败，不能回退示例数据。全局切换cloud不代表各接口都已可用。
- 保留本地草稿用于未提交输入；云端持久化后同一业务数据以云端为权威。接入须明确草稿迁移/丢弃规则，不能把本机袋和云袋同时显示为正式结果。
- 云数据库客户端权限默认拒绝私有/交易集合直写；公开目录仅暴露必要字段。管理员经受控流程核验身份和门店能力，不以首次访问、页面入口或测试PIN授予权限。
- 支付/退款外部调用放在数据库事务外，先持久化意图与预算，再通过可信结果/查单原子推进；重试、补偿和告警随资金能力交付。

## D04实施路线

选用确定性订单文档查找和显式真实写保护，详细义务只维护在[D04-SDK-INTEGRATION](D04-SDK-INTEGRATION.md)。这是一条待实现、待真实验收的正式订单接入路线，不代表SDK原生提供串行化读取。

- 沿用现有 `V1-` 加完整订单ID大写十六进制的生成规则；提供方须严格反解到同一orders文档、检查编号一致性，以主键新增和orderNo唯一索引保护。不依赖任意where谓词保护；不能兼容该映射的写入口须先迁移或另建原子唯一映射。
- 关键已存在依赖在同一事务获得真实写冲突保护；不存在的订单/回执必须同事务显式新增，缺用户/商品/配置直接拒绝。保护写入、业务写入和SDK重试均计预算；内部保护字段的字典、迁移、白名单和DTO边界先定义再实现。
- 原生读取/空查询探针用于诊断平台能力。观察到旧读仍能提交，应转入所选方案的验证；不把不具备的原生保护能力设为替代方案的前置条件。
- 保留预算、权限、资源、幂等和资金安全要求。方案真实验证失败时记录交错、平台响应与落库结果并修正实现；不能将保护接口改为恒真或删掉失败测试。冲突后的事务终止、未知清理失败与锁释放分别取证。

## 执行与验收

实施轮每次交付一个可运行的业务结果：必要单元回归→独立包构建/部署→真实接口调用与落库读回→相关权限/并发/设备检查；须在当轮用户授权范围内执行。部署复现、权限检查和真机冒烟从G1开始，Q阶段保留完整生产复现与联合验收。

跨域依赖按实际输入、安全约束与退出条件安排：地址CRUD不依赖购物袋整体验收；待付订单创建不依赖全部商家履约实现；商户/支付方案核验不依赖O08。订单保存依赖真实报价与D04事务，开放实付依赖完整资金恢复链，正式发布仍依赖全部V1验收。默认单agent，按具体交付切换工作，不另起同项并行实现。

测试结果分别记本地、真实云、真机、资金和生产发布；为结论附对应证据。同一源码状态已有成功结果不重复运行，新代码及真实影响域按AGENTS选验证范围。业务资料的唯一缺项清单为[EXTERNAL-DEPENDENCIES](EXTERNAL-DEPENDENCIES.md)，实际阻塞及下一步只维护在CURRENT-STATUS。
