# V1 开发任务索引

此处仅维护范围、依赖和验收要求，不维护进度、测试数量或排期预测；当前工作只查 [CURRENT-STATUS](CURRENT-STATUS.md)。67个任务保留；按本次任务读取对应阶段验收定义。用户最新要求优先于原计划。

共同门禁：真实业务以云端权限/数据/金额为权威；离线、云端、真机及资金证据分别判断。验收证据按需保留，不把内部模型当成已部署API，不使用旧定金/模拟支付替代V1。

## 实际执行顺序

按[ARCHITECTURE](ARCHITECTURE.md)的G1–G4交付：云商品/本人袋/地址 → 权威报价/完整订单 → 实付/商家履约/退款 → 生产验收发布。九阶段保留需求索引与最终退出条件，不代表必须将整个前一阶段验完才可开始下一项。

- 目录/地址/袋按自身数据及权限前置条件接入，不等待订单事务全部验收；D04按所选方案收敛验证，默认单agent按交付切换工作。
- 报价和订单保存须具备真实数据/并发保护；商家完整履约不是创建待付订单的前置条件。
- 支付商户/方案核验提前进行；开放实付前须具备权限、入账、查单/关单、退款与补偿路径。已确认经营/退款政策和最终V1范围不减少。
- Q01部署复现、Q04权限和Q06真机冒烟随每个接口开展；Q阶段仍要求完整联合与生产验收。
- 完成状态以已部署接口、页面实际调用和对应证据为准；按数据来源与影响范围更新开放标记，全局切换cloud不能认定全部能力可用。具体执行须遵守当轮授权范围。
